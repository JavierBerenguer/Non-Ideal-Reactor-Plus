Appendix

How to Prepare Experimental RTD Data for Import

Use this appendix before importing pulse or step data from Excel, CSV, TSV, MAT files, or the MATLAB workspace. The goal is not only to make the importer accept the file, but to make the reconstructed RTD physically meaningful once it reaches Tab 1.

What the Importer Really Needs

Item Why it matters
One monotonic time columnThe RTD reconstruction assumes the signal is ordered in time.
One response columnThis is the tracer concentration or measured signal used to reconstruct the curve.
Consistent unitsThe selected unit in the app must match the scale used in the file.
The correct experiment typePulse and step workflows do not interpret the same signal in the same way.
Important: the app can only interpret what you give it. A file that is syntactically valid but semantically wrong, for example a cumulative signal imported as if it were a pulse, can still produce a misleading RTD.

Expected Minimal Structure

Column Meaning
Column 1Time values
Column 2Measured signal or concentration response

For spreadsheet files, keep headers in row 1 and start numeric data in row 2.

Recommended Spreadsheet Layout

time,response
0,0
1,0.12
2,0.31
3,0.47

If you are importing from Excel, avoid merged cells, notes above the header row, and decorative columns between time and response.

Acceptable

  • Headers in the first row
  • Numeric data starting immediately below
  • Two clean columns for time and response

Risky

  • Units embedded inside numeric cells
  • Comment rows before the header
  • Hidden helper columns used for plotting

Pulse vs Step Reminder

  • Pulse data represent a tracer pulse response and should preserve the intended signal shape.
  • Step data represent a cumulative response and require a meaningful C0 when the workflow asks for it.
Experiment type Typical visual behavior What the app expects
PulseA peak that rises and decaysSignal suitable for RTD reconstruction from a pulse response
StepA cumulative rise toward a plateauSignal interpreted together with the selected baseline/concentration logic

Importing from the MATLAB Workspace

If you import from the workspace instead of from a file, the same logical structure still applies: the variable must resolve to clean numeric arrays with matching lengths.

  • Keep time and response vectors the same length.
  • Avoid cell arrays or mixed text/numeric containers unless you know the route supports them.
  • Make sure the workspace variable you type in the app actually exists in the current MATLAB base workspace.
t = [0; 1; 2; 3; 4];
c = [0; 0.12; 0.31; 0.47; 0.18];

Importing Signals in Tab 6

Import Experimental Data reads Excel (.xlsx or .xls), CSV, and TSV files. It uses the first two numeric columns as time and signal value, ignores any additional columns, and removes rows whose first two entries are not both numeric.

Import the file into the table for the signal you are defining: Cin(t), Cout(t), or E(t). Confirm the selected display units before calculating.

Pre-Import Checklist

  1. Confirm whether the experiment is pulse or step.
  2. Confirm the time unit used in the raw file.
  3. Remove notes, empty separator rows, and decorative columns.
  4. Check that time increases monotonically.
  5. Check that the response column is really the tracer signal you want to use.
  6. Only then choose the matching import route in Tab 1.

After-Import Sanity Checks

Do not stop at "the file loaded successfully". Once the data is inside the app, inspect the generated plots and moments.

  • If the signal shape looks inverted or cumulative when you expected a peak, revisit the pulse/step choice.
  • If τ is on the wrong scale, revisit the selected time unit.
  • If the RTD looks truncated, check whether the original dataset covers enough of the tail.
  • If later tabs behave oddly, verify the imported RTD before suspecting the chemistry.

Common Import Errors

  • Time is in minutes but the selected unit remains seconds.
  • The second column is not the measured signal but a different derived value.
  • The file contains extra blank columns or extra metadata rows before the numeric data.
  • The signal has been pre-normalized in a way that no longer matches the selected workflow.
