Minimum Recommended Workflow

If you are new to the app, follow this sequence before exploring specialized options. It mirrors the dependency logic of the current implementation and reduces most "missing object" or "why is this result strange?" situations.

1. Build or import the RTD in Tab 1 Start in RTD Analysis. This tab is the hydrodynamic entry point of the whole app. It generates the RTD, computes its moments, and can already hold a ReactionSys and a Stream.
2. Use Tab 2 if you want the direct RTD prediction route Use Prediction Models when you want the first reactive answer with the real RTD: Segregation, Maximum Mixedness, Ideal CSTR, and Ideal PFR.
3. Use Tab 3 or Tab 4 if you want a one-parameter prediction route Go to Tanks-in-Series or Dispersion Model when you want a one-parameter reactor interpretation that still depends directly on the RTD built in Tab 1.
4. Move to Tab 5 for fit, consolidated reactive comparison, or optimization Use Design & Optimization after the RTD is already meaningful and the chemistry is loaded.
Helpful companion: if you want a cross-tab explanation of how objects move, how restored sessions behave, and why a later tab may still need a fresh Compute, read the Cross-Tab Workflow appendix.

Tab Dependency Map

Tab 1 - RTD Analysis

Creates the RTD and its moments. This is the foundational hydrodynamic tab.

->
Shared objects

RTD, optional ReactionSys, optional Stream.

Tabs 2, 3, and 4 - Prediction routes

These are all prediction-model tabs: Tab 2 keeps the direct RTD route, while Tabs 3 and 4 use one-parameter equivalent interpretations.

->
Direct dependency

All three depend directly on Tab 1 as their hydrodynamic source and can optionally obtain both the reactive system and input data as well.

Tab 5 - Design & Optimization

Starts from the RTD of Tab 1 and organizes fit, reactive comparison, and optimization inside one workspace.

->
Subtabs

Diagnosis & Fit, Reactive Performance, and Optimization each reuse part of the same internal state.

Main practical rule: if something in a later tab says an RTD, a reaction system, or a feed stream is missing, go back to the nearest upstream tab and confirm that the object has really been created and loaded there.

Which Tab Should I Use?

If your goal is... Go to... Why
Generate an RTD, import experimental data, or inspect moments Tab 1 - RTD Analysis It is the only tab that builds the RTD itself.
Estimate real-reactor conversion bounds with the measured RTD Tab 2 - Prediction Models It compares Segregation and Maximum Mixedness directly against ideal references.
Approximate the reactor as N CSTRs in series Tab 3 - Tanks-in-Series It turns the RTD into an equivalent cascade model.
Study an axial-dispersion interpretation Tab 4 - Dispersion Model It expresses hydrodynamics through Pe / Bo and boundary conditions.
Fit equivalent families, compare several reactor models together, or optimize inlet conditions Tab 5 - Design & Optimization It is the integrated workspace for design-oriented analysis.

Before You Leave This Page

  • Tab 1 is foundational. If the RTD is not correct, the rest of the app is only propagating a wrong hydrodynamic description.
  • Tab 2 is the first reactive checkpoint. It is usually the best place to verify whether the chemistry and RTD combination gives sensible trends before using more specialized tabs.
  • Tab 5 does not replace Tab 1. It assumes the RTD has already been defined upstream and then organizes design-oriented tasks around it.
